## 2. P0：打通连接（当前最大痛点）

### 2.1 问题

实测踩到：**校园网在接入层做了客户端隔离**，同一 SSID 下手机和电脑互相不通。这不是防火墙问题，放行端口无效。

原理：隔离只掐"横向"（设备互访），不掐"纵向"（设备出网）。所以所有解法归为两类——**换物理链路**，或**反向穿透**。

### 2.2 方案清单

| 方案 | 原理 | 前提 | 代码改动 | 推荐度 |
|---|---|---|---|---|
| **A1 手机开热点** | 手机当 AP，自建无隔离局域网 | 无 | 无 | ⭐⭐⭐⭐⭐ |
| **A2 USB + `adb reverse`** | 手机 `localhost:8765` 经 USB 隧道转发到电脑 | Android + 数据线 + adb + USB 调试 | 无 | ⭐⭐⭐⭐⭐ |
| **B1 Tailscale** | 两端出站打洞，进同一虚拟内网 | 两端装 App + 账号 | 无 | ⭐⭐⭐⭐ |
| **A3 电脑开移动热点** | 电脑当 AP，共享校园网给手机 | 网卡支持并发模式；有线最佳 | 无 | ⭐⭐⭐ |
| **A4 USB 网络共享** | 手机经 USB 共享网络给电脑 | 手机能上网 | 无 | ⭐⭐⭐ |
| **A5 蓝牙 PAN** | 蓝牙建点对点链路 | 配对 | 无 | ⭐⭐ |
| **B4 IPv6 直连** | 部分校园网只隔离 IPv4 | 两端拿到 `2001:` 公网 IPv6 | 无 | ⭐⭐ |
| **A6 蓝牙 HID** | 手机直接当蓝牙键盘 | 仅 Android | 架构级改动 | ⭐ |

### 2.3 规划

**这三个方案都不需要改代码**，问题在于用户不知道要用哪个。所以规划的是**降低选择成本**：

- **v1.1**：启动时增加网段判断。检测到 `10.x` / `172.16-31.x` 等常见校园网/企业网段时，直接在提示里建议改用热点或 USB 方案
- **v1.1**：附一个 `tools/start-usb.bat`，自动执行 `adb devices` 检查 → `adb reverse tcp:8765 tcp:8765` → 提示用 `http://localhost:8765/?t=xxx` 打开
- **v1.2**：`--ip` 已支持手动指定；再补一个 `--check` 参数做自检（端口监听状态、防火墙规则、可达性）

## 3. P0：降低使用门槛

### 3.1 token 持久化（打包的前置条件）

**现状**：每次启动随机生成 token，导致 URL 和二维码每次都变，手机端书签全部失效。

**方案**：首次启动生成后写入脚本同目录的 `token.txt`（权限设为仅当前用户可读），后续启动读取复用。

```python
def load_or_create_token(explicit=None):
    if explicit:
        return explicit
    f = Path(__file__).resolve().parent / "token.txt"
    if f.exists():
        t = f.read_text(encoding="utf-8").strip()
        if t:
            return t
    t = secrets.token_urlsafe(6)
    f.write_text(t, encoding="utf-8")
    return t
```

**注意**：`token.txt` 要加进 `.gitignore`；打包成 exe 后，token 应写在 **exe 同级目录**而不是临时解压目录，否则重启就丢。

## 4. 打包成 exe（重点）

### 4.1 可行性结论

**完全可行。** `server.py` 只依赖 `ctypes`（标准库）+ `aiohttp`（纯 Python + C 扩展），没有 GUI 框架、没有动态加载的外部二进制，是 PyInstaller 的理想目标。

### 4.2 是否需要额外下载依赖？

分三个层面回答：

| 层面 | 是否需要的额外下载 |
|---|---|
| **构建机器** | 需要 `pip install pyinstaller`。`aiohttp` 及其依赖（`multidict`、`yarl`、`frozenlist`、`aiosignal`、`attrs`）必须已安装，**会被自动打进 exe** |
| **目标机器** | **不需要任何下载**。不需要 Python、不需要 pip、不需要联网 |
| **Windows 系统组件** | 可能需要 **VC++ 2015-2022 运行时**（`vcruntime140.dll`）。Windows 10/11 绝大多数情况已自带；PyInstaller 通常也会把它一并收集。**干净的精简版系统**上可能缺，需单独装 |

**关于 `qrcode`**：

- 打包时**装了** → 二维码功能正常
- 打包时**没装** → exe 里不含它，运行时走 `except ImportError` 分支，**只是不显示二维码，服务照常工作**

天然优雅降级，这是把 `import qrcode` 放进函数内 + try/except 带来的好处。

### 4.3 必需的代码改动（打包前先做）

**当前代码在打包后会找不到 `static/` 目录**，因为 PyInstaller onefile 模式下，程序运行时会把资源解压到一个临时目录。

`server.py:27` 现在是：

```python
STATIC_DIR = Path(__file__).resolve().parent / "static"
```

需要改成：

```python
def _base_dir() -> Path:
    """定位资源根目录，兼容源码运行与 PyInstaller 打包两种形态。"""
    if getattr(sys, "frozen", False):
        # onefile: 资源解压到 sys._MEIPASS
        # onedir : 资源位于 exe 同级的 _internal/
        return Path(getattr(sys, "_MEIPASS", Path(sys.executable).parent))
    return Path(__file__).resolve().parent

STATIC_DIR = _base_dir() / "static"
```

`getattr(sys, "frozen", False)` 是判断"是否被 PyInstaller 打包"的标准方式。

### 4.4 打包步骤

```powershell
# 1. 在项目根目录，装齐所有运行时依赖 + 打包工具
pip install -r requirements.txt
pip install pyinstaller

# 2. 打包（Windows 下 --add-data 的分隔符是分号 ;）
pyinstaller --onefile ^
            --name PhoneKeyboard ^
            --add-data "static;static" ^
            --collect-all aiohttp ^
            server.py

# 3. 产物
#    dist/PhoneKeyboard.exe
```

参数说明：

| 参数 | 作用 |
|---|---|
| `--onefile` | 打成单个 exe |
| `--name` | 输出文件名。**建议用 ASCII**，中文名在某些环境会有编码问题，产出后再重命名更稳 |
| `--add-data "static;static"` | 把前端资源打进包。格式是 `源路径;包内路径`（分号是 Windows 的写法） |
| `--collect-all aiohttp` | 兜底，确保 `aiohttp` 的所有子模块和 C 扩展都被收进去。**不加通常也能跑**（PyInstaller 自带 hook），出问题再加 |
| **不要加** `--windowed` / `--noconsole` | 必须保留控制台，否则用户看不到 URL 和二维码 |

### 4.5 exe 能不能直接在别的电脑上跑？

**能，但必须同时满足以下 5 条：**

| # | 前提 | 说明 |
|---|---|---|
| 1 | **同为 64 位 Windows** | 用 64 位 Python 构建 → 只能在 64 位 Windows 运行。32 位系统跑不了 |
| 2 | **Windows 版本 ≥ 构建 Python 的最低要求** | Python 3.12 要求 Windows 8.1+；实际建议 Windows 10/11 |
| 3 | **目标机器有 VC++ 运行时**（或系统已自带） | 缺了会报"缺少 vcruntime140.dll"。Win10/11 通常自带 |
| 4 | **防火墙放行** | exe 首次监听端口时，Windows 会弹窗（显示"未知发布者"）；或提前用 netsh 加端口规则 |
| 5 | **杀毒软件不拦** | 未签名的 onefile exe 是最容易被误报的形态 |

**明确不能的情况：**

- ❌ 不能在 macOS / Linux 上运行（PyInstaller **不支持交叉编译**，Windows exe 必须在 Windows 上构建；反过来也一样）
- ❌ 32 位 Windows 跑不了 64 位 exe
- ⚠️ ARM64 Windows 上，x64 exe 需要走系统模拟层，可能不稳定，最好是构建 ARM64 版本

**好消息**：我们之前给的防火墙规则是**按端口放的**（`protocol=TCP localport=8765`），不是按程序路径绑定的。所以换成 exe 后**规则依然有效**，不用重新加。

### 4.6 已知的坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **SmartScreen 拦截** | "Windows 已保护你的电脑" | 未签名 exe 必然遇到。让用户点"更多信息 → 仍要运行"。彻底解决要买代码签名证书（约 ¥1000+/年），对个人项目不划算 |
| **杀毒误报** | exe 被静默删除或隔离 | onefile 的自解压行为极易触发启发式查杀。对策：改用 `--onedir`；**不要用 UPX 压缩**（UPX 会大幅提高误报率）；必要时向厂商提交误报 |
| **启动慢** | 双击后 1~3 秒才出界面 | onefile 每次启动都要把内容解压到 `%TEMP%`。`--onedir` 没有这个问题 |
| **体积** | 约 12~18 MB | Python 解释器 + aiohttp 及其 C 扩展。属于正常范围，别用 UPX 压 |
| **中文文件名** | exe 名乱码或构建失败 | `--name` 用 ASCII，构建完再重命名 |
| **token 每次变** | 重启后二维码/URL 变了 | **必须先做 §3.1 的 token 持久化**，否则 exe 用起来很痛苦 |
| **路径含中文/空格** | 个别环境解压失败 | 尽量放在简单路径下 |
| **移动 exe 后失效** | 防火墙规则不匹配 | 我们的规则是按端口的，不受影响 |
| **打包后无二维码** | 终端只有链接 | 构建时忘了装 `qrcode` |

### 4.7 打包方案对比

| 方案 | 体积 | 启动速度 | 误报率 | 分发难度 | 评价 |
|---|---|---|---|---|---|
| **`--onefile`** | 12~18 MB | 慢（1~3s） | **高** | 最低（单个文件） | 适合偶尔传一个文件给对方 |
| **`--onedir`** | 20~40 MB（文件夹） | **快** | **低** | 中（要整个文件夹） | **推荐给正式分发**，还能单独替换 `static/` 里的前端 |
| **Nuitka** | 更小 | 最快 | 中 | 中 | 编译成真机器码，但构建慢、aiohttp 兼容性要调，收益不明显 |
| **嵌入式 Python + bat** | ~15 MB | 快 | 低 | 中 | 体积最小，但要手动铺包，维护麻烦 |
| **不打包，直接给源码** | ~20 KB | 快 | 无 | 高（对方要装 Python） | **如果对方是你自己/懂技术的同事，这才是最省事的选择** |

### 4.8 推荐路径

根据使用范围分三档：

**① 只有你自己的几台电脑用** → **不要打包**。

写个 `启动.bat` 就够：

```bat
@echo off
cd /d "%~dp0"
python -m pip install -q -r requirements.txt
python server.py --token demo
pause
```

双击即用，改代码立刻生效。打包反而会让你每次改代码都要重新构建。

**② 要给非技术同事用** → **`--onedir` 打包**，交付一个文件夹 + `setup-firewall.bat`（一键放行防火墙）+ 一页图文说明。

**③ 要发布给陌生人** → `--onedir` + 代码签名证书 + 完整的安装向导。投入产出比不高，除非真要做成产品。

### 4.9 打包后的配套待办

打包之前，这几件事应该先做完，否则 exe 体验会很差：

- [ ] **§3.1 token 持久化**（否则每次启动换地址，必须重扫码）
- [ ] 加 `--open-browser` 参数，启动后自动打开浏览器，省去手动复制 URL
- [ ] 把 URL 同时写进一个 `访问地址.txt`，方便复制
- [ ] 附 `setup-firewall.bat`（内容就是那条 `netsh` 命令，self-elevate）
- [ ] 把 `qrcode` 加入 `requirements.txt` 并确保构建环境已安装

## 8. 风险登记

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| 目标网络有客户端隔离 | 核心功能不可用 | **高（已发生）** | 内置网段检测 + 引导用户改用热点/USB 方案 |
| exe 被 SmartScreen/杀软拦截 | 用户打不开 | 高 | 优先 `--onedir`；不用 UPX；附操作说明 |
| token 未持久化 | 每次重启要重扫码 | **确定发生** | 打包前必须先修 |
| `SendInput` 被高权限窗口忽略 | 特定应用里不出字 | 中 | 属系统限制，无法绕过。文档中说明 |
| `SendInput` 被反作弊/安全软件拦截 | 游戏、远程桌面场景失效 | 中 | 文档说明，不承诺覆盖 |
| 依赖 PyInstaller 钩子失效 | 构建出的 exe 启动报错 | 低 | 用 `--collect-all aiohttp` 兜底 |
| Python 大版本升级导致 `ctypes` 结构体行为差异 | 注入失败 | 低 | 结构体定义已按 Win64 ABI 对齐，锁住依赖版本 |
