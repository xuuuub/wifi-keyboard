# 需求文档 — 手机当键盘

> 版本：v1.0
> 更新日期：2026-10-07
> 状态：已实现并验收（v1.0 范围）

---

## 1. 背景

### 1.1 问题场景

在图书馆、自习室、深夜宿舍等**需要保持安静**的环境里使用笔记本时，机械键盘或普通键盘的敲击声会干扰他人，也会让自己有心理负担。手机软键盘几乎无声，但它无法直接把文字输入到电脑上。

### 1.2 现有替代方案的不足

| 方案 | 问题 |
|---|---|
| 手机记笔记再传到电脑 | 要复制粘贴，打断思路 |
| 微信/QQ 文件传输助手 | 同上，且要手动操作 |
| 买静音机械键盘 | 有成本，且静音轴仍有声音 |
| 现成的远程键盘 App（Unified Remote 等） | 需装 App；部分要 root；国产环境下载麻烦 |
| 手机模拟蓝牙 HID 键盘 | iOS 不支持；中文要经过"输入法→按键码"映射，不稳 |

### 1.3 本方案的核心思路

不装 App、不改电脑、走浏览器：手机打开一个网页，输入的内容通过局域网实时注入到电脑光标处。手机端零安装（浏览器即可），电脑端只有一个 Python 脚本。

---

## 2. 目标与非目标

### 2.1 目标

- **G1**：手机打完字，文字出现在电脑**当前光标所在处**，无需在电脑上做任何"粘贴"动作
- **G2**：手机端零安装，浏览器打开即用
- **G3**：中文输入可用，且不经过电脑输入法
- **G4**：局域网内延迟低到"打字跟手"
- **G5**：不依赖任何第三方服务，数据不出局域网

### 2.2 非目标（v1.0 明确不做）

- ❌ 不支持 macOS / Linux（服务端依赖 Win32 API）
- ❌ 不做手机端 App
- ❌ 不做文件传输、剪贴板同步、屏幕共享
- ❌ 不做公网穿透（v1.0 假设手机和电脑在同一局域网）
- ❌ 不做多用户/多设备隔离

---

## 3. 用户角色

**唯一角色：使用者本人**

- 有一台 Windows 电脑（笔记本为主）
- 有一部智能手机（iOS 或 Android）
- 具备基本的命令行操作能力（能跑 `python server.py`）
- 使用场景通常在**没有独立路由器**的公共网络环境

v1.0 不考虑"分享给别人用"，因此不需要安装向导、图形界面、账号体系。

## 6. 非功能需求

### 6.1 性能

| 编号 | 要求 | 实测 |
|---|---|---|
| NFR-1.1 | 单字符从手机发出到电脑出字的端到端延迟 < 100 ms（局域网） | 通常 < 20 ms |
| NFR-1.2 | 单次注入耗时可忽略（不阻塞事件循环） | `SendInput` 是同步调用，微秒级 |
| NFR-1.3 | 长文本注入不导致界面卡死 | 逐字符注入，无明显卡顿 |

### 6.2 可靠性

| 编号 | 要求 |
|---|---|
| NFR-2.1 | 单条脏消息不得导致连接断开 |
| NFR-2.2 | 电脑端网络抖动后，手机端应能自动恢复，无需手动刷新 |
| NFR-2.3 | `SendInput` 失败（如目标进程权限更高）时服务不崩溃 |
| NFR-2.4 | 二维码渲染失败（终端编码不支持）不得阻断服务启动 |

### 6.3 易用性

| 编号 | 要求 |
|---|---|
| NFR-3.1 | 从零到可用不超过 3 步：装依赖 → 跑脚本 → 扫码 |
| NFR-3.2 | 软件键盘弹出时布局自适应，不遮挡输入区 |
| NFR-3.3 | 适配刘海屏/挖孔屏/底部手势条（安全区） |
| NFR-3.4 | 按钮触控区域足够大，误触率低 |

### 6.4 安全

| 编号 | 要求 |
|---|---|
| NFR-4.1 | 默认仅监听局域网，不主动连接外网，数据不出局域网 |
| NFR-4.2 | 未携带正确 token 的连接一律拒绝 |
| NFR-4.3 | 服务端不解析执行任何来自客户端的代码，只处理白名单消息类型 |
| NFR-4.4 | 客户端传入的 `count` 等数值必须钳制上界 |

### 6.5 兼容性

| 编号 | 要求 |
|---|---|
| NFR-5.1 | 手机端支持 iOS Safari / Android Chrome 及主流国产浏览器 |
| NFR-5.2 | 电脑端支持 Windows 10 / 11（Python 3.8+） |
| NFR-5.3 | 不依赖任何浏览器扩展或 App |

## 7. 约束与假设

### 7.1 硬约束

- 服务端必须运行在 **Windows**（`SendInput` 是 Win32 API）
- 必须能访问到电脑的某个 IP 端口（局域网直连、热点、USB 隧道、或穿透）
- 电脑需要安装 **Python 3.8+** 和 `aiohttp`

### 7.2 关键假设

| 假设 | 风险 |
|---|---|
| 手机和电脑在同一局域网 | ❌ 校园网/公共 Wi-Fi 有客户端隔离，**已被实际踩到** |
| 用户愿意在电脑上跑一个 Python 脚本 | 中，见《未来计划》的 exe 打包 |
| 用户输入以"从后往前编辑"为主 | 中，中间插入会错位 |
